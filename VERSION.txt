0.4.0

## Changelog

### 0.4.0 (2026-06-26)
- **Home-media subsystem — built, deployed, and verified live on Camperoku.** Browse/play home-made camping trips + photos on the Roku, served from the HDD via `sally-api`.
- Encode-once "gold standard": MP4 H.264 High@L4.2, ≤1080p downscale-only, CFR, 2 s GOP, CRF 20 + 12 Mbps cap, AAC 192k, `+faststart` (verified by `ffprobe` on a real Pi encode). Codec config-switchable for HEVC on the N100.
- New pipeline (`scripts/` → `/opt/sally/media/`): `media-ingest.sh` (filesystem queue, sha256 dedup, atomic publish, rollback-on-fail), `media-encode-video/photo.sh`, `media-extract-meta.py` (exiftool + geotag chain: embedded GPS → GPX breadcrumb correlation), `media-track-logger.py` (gpsd→GPX on SD), `media-reindex.py`, `media-worker-remote.sh` (laptop offload). systemd: always-on track logger + nightly idle-prio encode timer (won't fight RetroPie). HDD tree `/mnt/usb/home/`.
- `sally-api` extended (additive to the frozen v1 contract): `/api/media?type=trips`, `/api/collections/<id>`, `/api/photos`, `/media/<path>` (HTTP Range 206), `/api/qr.png`, `/api/upload` + `/upload` mobile page; served under waitress. Per-item sidecars = source of truth; `catalog.json` + breadcrumbs on the Pi SD card.
- Guest upload: QR on the Roku Photos screen → phone upload page (camera roll, optional name/trip/GPS) → inbox → encodes overnight.
- New Roku screens: Media (RowList rows-as-trips), `VodPlayer` (trick play + resume bookmark + watchdog, EOF→back), PhotoGallery (slideshow), QrScreen; Media + Photos tiles enabled.
- ⚠️ HDD bad sector found (Seagate ST1000LM037, unrecovered read error) — localized; decision: leave-as-is + monitor; mitigated by relocating catalog/tracks to SD. See `docs/current-state.md`.
- Platform decision: stay on Pi Buster for now (version-aware ffmpeg 4.1 / Py3.7 workarounds); modern stack lands on the N100 at Phase 3.

### 0.3.0 (2026-06-26)
- **Phase 0 of the SallyNet glass dashboard — built, sideloaded, and verified live on Camperoku** (renders live drive data; other tabs are placeholders).
- New `services/sally-api/` — Flask backend on the Pi (`:8090`, systemd unit) serving `/api/state` live from gpsd: the single HTTP surface the Roku polls (+ `/api/discovery`, `/api/health`). Frozen contract in `subsystems/media/api-contract.md` (sections omitted, never `null`).
- GPS operational: u-blox 8 (UBX-M8030) on the Pi, `gpsd 3.17` serving a 3D DGPS fix. Buster apt repointed to `legacy.raspbian.org` to install (EOL-mirror fix).
- New `roku-channel/` — the **SallyNet** Roku channel (forked from `rokuApp`/HouseWall + Delta Cam toolchain): Splash→Home→Drive route stack, `StatePollTask` poll loop, auto Drive/Home modeController, sunset branding + mascot.
- Repo **consolidated to a single git repo** at `sallyNet/` — Roku channel folded into `roku-channel/` (was a separate repo).
- Decisions locked: MQTT-first (no Home Assistant on the critical path); backend = Pi stopgap → N100 at Phase 3; audio = RF headphones (movies) + BETS-1 FM (music); tanks = reuse 1980s probes via ESP32 + CD4051; media = `/api/media` (encode-once MP4), retire MiniDLNA for the Roku path; fuel logger = ESP32 keypad + OLED at the driver's door (supersedes the cabin-numpad plan).
- Master plan captured; docs swept for stale references (gps / media / tanks / telemetry / current-state / CLAUDE.md / network-diagram).

### 0.2.0 (2026-05-17)
- New `subsystems/audio/` — unified audio system with three simultaneous output paths (Snapcast over WiFi to phones, BT A2DP to one of four owned speakers, BETS-1-legal FM broadcast); QX-18 USB handheld mic for PTT/PA mode
- Architecture decision: **mini-PC (Intel N100 class) becomes Sally's always-on services host** — runs audio, telemetry collector, Roku channel media server, MQTT broker, gpsd. Avoids ESP32 WiFi+BT radio conflict learned from the Halloween project (separate physical radios on x86).
- Pi 3B stays untouched as the pure RetroPie appliance — no service cohabitation
- New `subsystems/comms/amateur-radio-path.md` — Canadian Amateur Radio Basic Qualification path documented as the **legal** answer to camper-to-camper duplex voice. ISED RIC-40 + BETS-1 research determined the FM-band-duplex idea was not legally viable.
- Hard rule recorded in `subsystems/audio/fm-broadcast.md`: BETS-1 cap is < 1 µW EIRP; no power amps, no high-gain antenna stacking
- Cross-references updated across compute, telemetry, media, comms, network-diagram, and CLAUDE.md
